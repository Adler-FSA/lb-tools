# 02 – Demo, Onboarding und UX-Standard

## Demo als eigener Betriebsmodus

Die Demo ist kein bloß vorausgefülltes Formular. Sie ist ein eigener Modus mit eigenem Datenbestand und eigenen Schutzregeln.

### Regeln
- Demo-Daten bleiben vollständig erhalten.
- Demo wird sichtbar als Demo gekennzeichnet.
- Demo darf persönliche Daten nicht überschreiben.
- Persönliche Sicherungen dürfen nicht versehentlich in der Demo übernommen werden.
- Demo-Exporte tragen immer `DEMO-` im Dateinamen.
- Demo muss vollständig bedienbar sein.
- Demo eignet sich gleichzeitig als Funktions- und Sicherungstraining.

## Stress-Test-Demo

Die Daniel-Muster-Demo der Notfallakte bleibt bewusst groß.

Sie testet:
- viele Datensätze
- lange Texte
- viele wiederholte Bereiche
- Seitenumbrüche
- große Excel-Dateien
- große JSON-Sicherungen
- lange PDFs
- Dateinamenslogik
- Ausgabe auf unterschiedlichen Browsern

Für neue Produkte soll die Demo den maximal sinnvollen Funktionsumfang zeigen, nicht nur drei Beispielzeilen.

## Onboarding

Beim ersten Start werden zwei Wege angeboten:

### Neue Nutzung
1. direkten Produktzugang sichern
2. eigenen Sicherungsordner anlegen
3. Demo ansehen
4. Sicherungsablauf an der Demo trainieren
5. Excel-/PDF-Ausgabe kennenlernen
6. erst danach persönliche Daten beginnen

### Bestehender Datenstand
- vorhandene Master-Sicherung auswählen
- Daten wiederherstellen
- Ergebnis prüfen

Das Onboarding muss später erneut aufrufbar bleiben.

## Sichtbare Bestätigungen

Jede relevante Aktion bekommt eine sichtbare Rückmeldung.

Beispiele:
- Änderung gespeichert
- Demo geöffnet
- eigene Version geöffnet
- Datei erzeugt
- Datei wiederhergestellt
- Import abgeschlossen
- Download gestartet
- Daten gelöscht

### Aktionsbox
Standardbestandteile:
- klarer Titel
- verständliche Erklärung
- Dateiname, falls relevant
- optionale weitere Aktionsbuttons
- `Bestätigen`

Nutzer dürfen nie rätseln, ob ein Klick funktioniert hat.

## Akademie-Erklärungen

Erklärungselemente sollen nicht nur sagen, **was** zu tun ist, sondern auch:
- warum
- wofür
- was danach geschieht
- welche Folge eine Entscheidung hat

Dafür werden bevorzugt Klappreiter und kompakte Akademie-Wissen-Boxen verwendet.
